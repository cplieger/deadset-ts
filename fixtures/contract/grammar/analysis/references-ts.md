# References in TypeScript

Rules `references-ts.1` to `references-ts.41` of [the analysis](../analysis.md). A rule is cited by its id, which is never reused for another rule.

## Module URLs

**references-ts.1** In a source file of the program, `new URL(<string>, import.meta.url)`, where `URL` names the platform's `URL`, with the string a string literal or a template literal with no substitution that is a relative URL reference, and `import.meta.resolve(<string>)`, with the string such a literal that starts with `./` or `../`, name the file the string resolves to against the file's own directory, as a relative specifier of a configuration file resolves, its query and its fragment removed. A URL reference is relative unless it is empty, starts with `/` or carries a scheme ([URL Standard](https://url.spec.whatwg.org/#relative-url-string)), so `new URL("worker.js", import.meta.url)` names the file beside the calling file as its `./` spelling does. A runtime starts that file as a module, a worker among them. The expression is an import of the file for its effects, written where the expression is: the file joins the import graph there, its top level is referenced from the declaration that holds the expression, or from the holding file where the expression is in no declaration, so it is live while that is, and no export of it is referenced. A file only test code loads this way is test-support code. `URL` names the platform's `URL` unless the analysis proves it the target's own, as `roots.23` proves a `require`'s callee. So an import of `URL` from `node:url`, which exports the class the global names ([Node `URL`](https://nodejs.org/api/url.html#class-url)), a declaration of the target that merges into the global, such as an interface a `declare global` block declares, and one in a declaration file or under a `declare` modifier, which only types it, each leave it the platform's. The constructor, parentheses removed, is read where it is a name of `URL` as `roots.23` reads a name of `require`: written as the name `URL` or as a member named `URL`, so `url.URL` and `globalThis.URL` build a module URL too, named `URL` by an import, a re-export or a destructuring that carries it, so a renamed import of `URL` does, or a variable of the target whose initializer is such a name.

**references-ts.2** A worker address, the first argument of `new Worker`, `new SharedWorker` or `navigator.serviceWorker.register`, names the file the runtime starts, and the call is an import of that file for its effects written where the call is, as `references-ts.1` reads a module URL: the file joins the import graph there, its top level is referenced from the declaration that holds the call, so a worker started only in a declaration nothing references reaches its file from dead code only, and no export of it is referenced. An address built as a module URL is that module URL. An address written as a string literal or a template literal with no substitution is a URL reference read against the calling file's directory, as `references-ts.1` reads one, so a bare name names the file beside the calling file and one with a scheme or a leading `/` names no file of the target. The constructor or `navigator`, parentheses removed and read through a property access such as `globalThis.Worker`, is the platform's where its name resolves to a symbol that is no alias and has a declaration outside the target's files, so a declaration of the target that merges into it leaves it the platform's, while a declaration only the target writes and a package's global alias address no worker; a name the checker leaves unanswered is the platform's. A `Worker` that resolves, through the import or the `require` that binds it, each read as `conventions.3` reads a binding of a module with the checker resolving the `require`, the namespace that holds it, or the module declaration that declares it, to the `Worker` of `worker_threads` or `node:worker_threads` is Node's: its string address is a path read against the working directory ([Node `Worker`](https://nodejs.org/api/worker_threads.html#new-workerfilename-options)), which the analysis reads as the directory of the manifest nearest the calling file, where a package manager runs the package's scripts ([npm scripts](https://docs.npmjs.com/cli/v11/using-npm/scripts#best-practices)); only a path that starts with `./` or `../` names a file, an output path naming the own file the project emits it from. An address built as a call of `join` or `resolve`, through any name, whose first argument is the calling file's own directory, a `__dirname` no scope of the file declares or `import.meta.dirname`, and whose other arguments are each a string literal or a template literal with no substitution, is the path those literals join to against that directory, and names a file only as Node's `Worker` reads it; an address with any other argument names no file. An options argument written as an object literal whose `eval` member is anything but `false` makes the string code, which names no file.

## Module namespace objects

**references-ts.3** A module namespace object is the binding of a namespace import, `import * as ns`, the value an `await` of a dynamic `import()` produces, the first parameter of the first callback passed to `then` on a dynamic `import()` call, and the binding of a `const`, `let` or `var` declaration whose initializer is one of these: a write to such a binding is a use of the object the second rule below reads as every export, so a binding the program reassigns references every export. A dynamic `import()` names a module when its argument is a string literal or a template literal with no substitution that the program's module resolution maps to a source file. An identifier that spells the binding's name without referring to it is no use: a property name an object literal, a class, an interface, a type literal or an enum declares, a JSX attribute's name, and a statement label with the `break` and `continue` that name it. A use of a namespace object references the module's exports by what it reads:

- **references-ts.4** A property access by name, `ns.name`, or by an index that is a string literal or a template literal with no substitution, references the export of that name, a re-export walked to the declaration it carries, and so does each property an object binding pattern destructures from the object.
- **references-ts.5** Any other use references every export of the module, because code the analysis does not follow may read any export through the object: the object or the `import()` call passed as an argument, returned, assigned to anything but such a binding, stored in a property or an element, spread, or indexed by any other expression, a `typeof` query of it included.
- **references-ts.6** A namespace object nothing uses references no export, and neither does a dynamic `import()` whose value is not used, being an expression statement, a `void` operand or an `await` whose result is not used: the call loads the module and nothing more.

## Module declarations

**references-ts.7** A `declare module` declaration whose name is a string literal, an augmentation of a module in a module file or an ambient module declaration in a script, is referenced by each import of the program that names its module. An import names the module when its specifier equals the declaration's name or when both resolve to the same source file. Where the declaration's name holds one `*`, an import names it when its specifier matches the name with the `*` standing for any run of characters. Such a wildcard declaration is how the compiler types the file a matching specifier names, so an import that names it by its pattern references it, and each member of it the import names, as a reference from production code, whether a test file or a production file writes the import. An import here is an import or a re-export declaration, a dynamic `import()` whose argument is a string literal or a template literal with no substitution, an `import x = require()` declaration and an import type, in any file of the program, the declaration's own file included. An import in a file that no configuration of the run holds names no module declaration, because no compiler run reads the declaration for that file. The reference is recorded at the import and held by the declaration that holds it, or by the file where the import is a top-level statement. An import that names a module declaration also references each member of it that the import names, the `default` member for a default import, the member of each name a named import or re-export lists and every exported member for a namespace import, whether or not the specifier also resolves to a source file, a component file among them. A module declaration is used as well where a declaration it holds is used, as a `declare global` block is, because it may augment a module no import of the target names, whose declarations code outside the analysis types values by. A module declaration no import names and none of whose declarations is used is reported whole under `DS1002`, and its members fall with it. While an import names it, each member of the declaration is judged as any other member of the program is, by its own references.

**references-ts.8** A `declare global` block, and every namespace nested in it, is used where a declaration it holds is used. An interface or a namespace declared at the top level of a file that is no module is a declaration of the global scope, as one such a block holds is, and the next sentence holds of it too. A member such a block merges into an interface the compiler's library declarations declare, `ImportMeta` or `Window` among them, is read where a read of that interface's member resolves to it, and it is judged by its own references as any member is. Such an interface that is ambient, written in a declaration file or under `declare`, and that merges into an interface declared outside the program's own files, is how the compiler types the value the runtime provides, so a read of a member it declares reads it as a reference from production code, whether a test file or a production file writes the read, a test file's read being held by that file's top level. An interface such a block or such a file declares that merges into an interface declared outside the program's own files is used, and so is every interface, namespace and block between it and the global scope, because the outside declaration names it wherever a value is typed by it. Where every such outside declaration is a package's, not the compiler's library declarations, and declares no member, each member the interface declares is used as well: the package reads such an interface by type, as `keyof` does, in declarations the analysis does not walk. In a library, a published workspace member of an application included, every declaration a `declare global` block holds is published API, as a declaration a manifest entry reaches is, where the block is in a file a published entry point names or in a file that holds a published declaration: the consumer's compiler loads that file's typings, and the global scope they declare, with the published API.

## Overrides of outside classes

**references-ts.9** A method, an accessor or a property of a class of the target, static or not, that overrides a member of a class declared outside the target and its loaded consumers, in the compiler's library declarations or in a dependency, at any depth of the class's `extends` chain, is used by code outside the analysis that holds the instance or the class through that class: that code calls the method, reads the accessor or the property, and may write it. A class of the library declarations is an interface and a variable of one name, as `Error` and `Map` are, and a class whose chain reaches `Error` overrides its `toString` as well, which the runtime calls to print the error though the library's `Error` interface omits it. The member counts as read by the class that declares it, so it is live while that class is, it falls with the class when the class is dead, and it is never reported under a code of its own, as unused or as written and never read. A class keeps its place where its class declaration is: a declaration of the target that merges into a class declared outside the target, such as an interface a module augmentation declares, does not bring the class into the target.

## Overrides in the target's own classes

**references-ts.10** A use of a method, an accessor or a property through a value of a class type of the target, `this` inside the class's own members included, reaches the member it names and each member of a subclass of the target that overrides it, at any depth of the subclass's `extends` chain, because the runtime dispatches on the instance. An abstract member is referenced where such a use names it, and its overrides are live while it is.

## Members reached through types

**references-ts.11** A value reaches a position typed by a type when it initializes or is assigned to a declaration, a property, an element or a parameter that type annotates, when a function whose result type annotates returns it, and when a `satisfies` expression checks it against that type. An `as` expression is no such position. Where the value's type and the position's type differ, the value's type reaches the position's type, and a pair of types reaches as follows:

- **references-ts.12** An object type reaching an object type reads each member of the first that the second declares under the same name, because the compiler reads the member to check the assignment and code holding the position reads it through the position's type. A union or an intersection on either side is compared constituent by constituent, and a constituent of the value's type that is a constituent of the position's type reads nothing. A property of a mapped type over literal keys, `Record<"id", number>` among them, is a member the type declares under that name, although no declaration writes it, and no member of the value's type is that property.
- **references-ts.13** An array or a tuple reaching an array or a tuple reaches through its element types. A function type reaching a function type reaches through each pair of a call signature of the value and a call signature of the position, and a constructor type through each pair of construct signatures: each parameter type of the position's signature reaches the parameter type in the same place of the value's signature, and the value's result type reaches the position's result type. An overloaded function so reads each member any of its overloads' parameters declares, which reads more and never less than the overload the compiler resolves. An instantiation of a generic type reaching an instantiation of a generic type with as many type arguments reaches through its type arguments, each reaching the one in the same place, and an array or a tuple reaching an instantiation with one type argument reaches through its element type to that argument, as an array reaches `Iterable<T>`. The walk compares the arguments by place and not by the variance of the type parameters, which reads more and never less.
- **references-ts.14** A pair reaches once, so the walk ends when no pair joins.

**references-ts.15** A member read through a value whose type is a type parameter of a generic function reads the member of that name on each type a call of that function passes for the parameter, read off each parameter whose declared type holds the type parameter, directly or as a type argument, against the type the call passes there, because the value the read reads is the call's. A `for…of` statement and a spread element read the `[Symbol.iterator]` member of their operand's type, and a `for await…of` statement reads its `[Symbol.asyncIterator]` member and its `[Symbol.iterator]` member, which the statement falls back to, each at the operand, because the language calls them to iterate.

**references-ts.16** A property of an object literal writes the member of its contextual type that `DS1301` in [`kinds.json`](../../kinds.json) names, and a read of that property through a value of the literal's own type, a declaration the literal initializes without an annotation included, reads that member.

**references-ts.17** A value whose type is declared outside the target and its loaded consumers, in the compiler's library declarations or in a dependency, that reaches a position typed by an object type of the target reads each member of the target's type that the value's type declares under the same name, because code outside the analysis holds the value and reads those members.

**references-ts.18** An object literal that is an argument of a call or a `new` expression whose callee has no implementation in the target reads each member of the type of the parameter it is checked against, as the call instantiates that type: each constituent's, for a union or an intersection, and the instantiated type where the declared one names a type parameter, so `items.push({ shown, hidden })` on an array of a target type reads both members. Where a property's value is itself an object literal, that literal's members are read in the same way, against the type of the member it initializes. A callee has no implementation in the target when the declaration of the signature the compiler resolves the call to has no body and nothing of the target stands for it. A function, a method, an arrow function, a function expression or a class of the target stands for the signature when it is the callee itself, or when it reaches, under the rule above, the declaration, the parameter or the property from which the callee's value is read. A value passed for a parameter reaches it only through a call that names the function declaring the parameter, so a function value passed through any other call leaves the callee with no implementation, which reads more. A class or an object literal of the target that implements an interface stands for that interface's method, call and construct signatures. The implementation of a target overload set stands for each of its overload signatures, and an override a target class declares stands for the abstract method it overrides. So each of these has no implementation in the target: a function declared in a declaration file or in an ambient context, a member of a `declare global` block's interface no target class or object implements, a function or a method that a dependency or the compiler's library declarations declare, and a call or construct signature of a type the target declares, held by a value no function or class of the target reaches, such as a value read off a global through an `as` expression. The rule reads an object literal written at the argument and nothing else: a value of the same type that a declaration holds and the call passes by name has its members written where its own literal is, and reads only what a read of it reads.

**references-ts.19** An `as` expression whose operand, through further `as` expressions and parentheses, has an object type no file of the target declares, and a `new` expression whose callee has no implementation in the target and whose signature's result is no type parameter, hand the target a value code outside it holds. Every member of each object type of the target that expression's type has is read, recorded at the expression. An `as` expression over a value of type `any` hands over nothing, so a decoded value asserted to a type of the target reads only what the target reads of it.

## Object spreads

**references-ts.20** A spread element `...x` of an object literal reads each member of the type of `x`, of each constituent where that type is a union or an intersection, that the spread copies. The runtime copies the value's own enumerable properties, so the spread reads each property and field of the type, a property an interface or a type literal declares included, and an accessor an interface or a type literal declares is read as a property is. It reads no method and no method signature, whoever declares it, because a spread copies a function and calls none, no accessor a class declares, which sits on the class's prototype, and no `#private` name, which is no property. A member is a class's method or accessor by its declaration, whatever type reaches it, so a mapped type over a class instance type, `Readonly<C>` among them, reads no accessor of `C` through a spread. The reads are recorded at the spread element and held by the declaration that holds it, or by the file where the literal is a top-level expression.

## Indexed-access types

**references-ts.21** An indexed-access type `T[K]` whose index type `K` is a literal type, a string literal type or a numeric literal type, or a union of literal types, references each member of `T` that one of those literals names, as a property access by that name does. Where `K` is a union mixing literal types with other types, its literal constituents are read so, and the others read nothing. Where `K` is a type parameter whose constraint is a literal type, a union of them or a type alias naming one, with no `keyof` in it, the access references each member of `T` the constraint's literals name, because the compiler accepts the access only while `T` declares each of them. The reference is recorded at the indexed-access type and held by the declaration that holds it.

**references-ts.22** An indexed-access type that names a type parameter is read after each type parameter it names is replaced by the type argument the reference or the call holding it fixes. A reference to a generic type alias, interface or class fixes the type arguments it writes. A call or a `new` expression fixes the type arguments of the signature the compiler resolves it to: the ones it writes, the ones the compiler infers from its arguments, and the ones bound by the instantiation of the generic declaration the callee is a member of, a dependency's declaration included. A `new` expression fixes them as a call does, its resolved signature being the construct signature of the class's constructor or of a construct signature type, and a class's parameters are its constructor's. A receiver's type argument is the one the instantiation of the generic declaration the callee is a member of has, whether the receiver's type is that instantiation or a class that extends it, directly or through other classes, `this` included. The callee is that resolved signature, whatever expression names it, a generic function an object literal's property holds included: a property access, a member of a namespace import, an alias, or a binding that an object binding pattern destructures from a value of an instantiated type. So `const { get } = createStore<Fields>()` followed by `get("title")` reads `Fields["title"]`, as `createStore<Fields>().get("title")` does. An inferred type argument is the type the compiler gives the argument, so a `const` binding, a member of an object an `as const` assertion fixes, an enum member and a template literal with no substitution each fix the literal type the compiler gives them. The substitution follows a generic alias's body, both branches of a conditional type and the members of a generic declaration. It reaches every indexed-access type held by the resolved signature's parameter and result types, through unions, intersections, array element types, type arguments, the members of an object type literal and the parameter and result types of a function type. So `Payloads[K]` inside an alias that a call fixing `K` to `"open"` instantiates references the member `open` of `Payloads`. A reference inside a mapped type `{ [K in U]: G<K> }` fixes the type parameter of `G` that its argument `K` names to `U`, so `{ [K in Kind]: Kinded<K> }` reads each member of `Payload` that `Payload[K]` in `Kinded` names for each literal of `Kind`.

**references-ts.23** The resolved signature has two kinds of `keyof` position. One is a type parameter of the signature whose constraint holds `keyof O`, read through generic aliases and conditional types as the substitution above reads them: the constraint itself, a constituent of a union or an intersection, or the checked type or a branch of a conditional type, so `K extends keyof O` and `K extends Extract<keyof O, string>` are both such positions. The other is a parameter whose declared type holds `keyof X` in the same way, where `X` is a type parameter of the signature or of the generic declaration the callee is a member of, so `clear(event?: keyof M)` on a member of `Bus<M>` is one, or any other type, the signature generic or not, so `clear(event: keyof Events)` is one too. A parameter that is optional is such a position as the same parameter written required is, its `undefined` constituent naming no member. Where the call fixes such a type parameter, or passes such a parameter an argument the compiler types, as a literal type or a union of literal types, each member of `O` that one of those literals names is referenced, as by the indexed access `O[K]`, whether or not the signature writes one. `O` is the type the resolved signature substitutes for the operand of `keyof`: the receiver's type argument where the operand is a type parameter of the generic declaration the callee is a member of, the call's own type argument where it is one of the signature's, and the operand itself where it is neither, as in `at<K extends keyof Fields>(key: K)`.

**references-ts.24** Where an index so read is a literal type or a union of literal types, the access references each member of the type that one of those literals names. The reference is recorded at the reference or the call that fixes the index and held by the declaration that holds it. A literal names the member the type declares under that name and nothing else. In a type that also declares an index signature, the declared members are read by the literals that name them, and a literal that names no declared member reads the signature, which is no member. An indexed-access type whose index is any other type references no member under this rule.

## Element access by a literal type

**references-ts.25** An element access expression `o[k]` whose index expression the compiler types as a literal type or a union of literal types references each member of the type of `o` that one of those literals names, as a property access by that name does: a read where the access is read, a write where it is the target of an assignment, and both for a compound assignment, an increment and a decrement. A string literal index is the case of one literal. An index typed `keyof T`, for a type `T` that declares no index signature, is the union of the names of `T`'s members. An index the compiler types as a type parameter is read as the type its constraint admits, because the function body serves every instantiation. An element access whose index the compiler types any other way references no member under this rule. Where the receiver's type is `any` or declares no string index signature, `reflective-lookup` in [`exemptions.json`](../../exemptions.json) may retain a member a string literal names.

**references-ts.26** Where the index is a parameter of the function that encloses the access, the function's body never assigns that parameter, and every call of the function is one the target holds, the members the access references are decided at the function's calls instead. The body assigns the parameter where it is the target of an assignment, a destructuring assignment at any depth among them, of a compound assignment, an increment or a decrement, or of a `for…in` or `for…of` statement that declares no variable. Every call is one the target holds when the function is a function declaration, or a `const` variable whose initializer is an arrow function or a function expression, that is not exported, and every use of its name in its own file is the callee of a call, because a method may be called through a base class or an interface, an exported function from a program outside the target, and a function used as a value from a call the target cannot pair with it. At each call of the function the target holds, the access references each member of the type of `o` that the type the compiler gives the call's argument at that parameter names, under the rule above, recorded at the call, with the access's own kind of reference. A call that passes no argument there references the members the type of the parameter's initializer names, and nothing where the parameter has none. So `const at = (key: keyof Fields) => fields[key]`, called as `at("title")` and `at("body")`, reads `title` and `body` and no other member of `Fields`. Wherever any of these conditions fails, the access is read at the access by the rule above, through the type the compiler gives the index there, because a caller the target cannot pair with the function may pass any key that type admits. Where the type of `o` names a type parameter of the function, the access is read at each call after the substitution the call makes, as an indexed-access type is.

**references-ts.27** A string or number literal compared by `===`, `!==`, `==` or `!=`, or written as a `case` label of a `switch`, with an operand whose declaration's type holds `keyof X` references the member of `X` that the literal names, because the comparison selects the code that handles that key. The operand's declaration is read through an import or a re-export that names it, and the reference is recorded at the literal.

## Schema bindings in TypeScript

**references-ts.28** A protoc-gen-es file of row `protoc-gen-es-2` names each declaration through the `@generated from <kind> <name>` tag of its JSDoc comment, read through the compiler's JSDoc API and never from the embedded base64 descriptor, and its schema file through its `@generated from file <path>` tag. A field tag spells the field's options after its number, `= 7 [json_name = "sync"];`, so the number is read before an optional bracket. A `<Msg>Schema` or `<Enum>Schema` constant carries no tag and binds through its declared type's argument, `GenMessage<T>` or `GenEnum<T>`, which names the tagged type. A service is a `GenService` constant: the constant is the service's consumer, and each property of its type argument, spelled in the literal-member form of [the reference grammar](../symbol-ref.md), is the consumer of its RPC. A oneof member binds to its constituent in the case-constituent form.

**references-ts.29** A protoc-gen-es file of row `protoc-gen-es-1`, and a protoc-gen-connect-es file of row `protoc-gen-connect-es-1`, name a message through its class's `static readonly typeName`, a field through the `{ no, name }` entry of the class's `fields` list, an enum and its values through `setEnumType(…, "<pkg>.<Enum>", [{ no, name }])`, and a service through its literal's `typeName` and `methods`, each method's literal member being the consumer of its RPC.

**references-ts.30** A ts-proto file of row `ts-proto-2-output-schema` names each message and service through the descriptor object literal it embeds and the literal's `references` map, and a field by joining the descriptor's field number to the interface property that the generated `decode` assigns under `case <number>:`; a `oneof=unions` member joins the same way through the `$case` object `decode` builds. Its schema file is its `// source:` line. An RPC binds through its client method and the service `path` literal `"/<pkg>.<Svc>/<Rpc>"`, and the service through the `<Svc>ServiceClient` constant and interface and the `<Svc>Service` definition. The synthetic `UNRECOGNIZED` enum member binds nothing.

**references-ts.31** A ts-proto file of any other option set binds its services and RPCs as `references-ts.30` states where it writes a service `path`, which is row `ts-proto-2` and a fallback of scope `types` for the file's other declarations, and binds nothing where it writes none, which is row `ts-proto-2-types` and a fallback of scope `all`. A client method is one consumer whatever its overload count.

**references-ts.32** A TypeScript oneof member's constituent is read by an access of the constituent's member property on a value control flow has narrowed to that constituent, `value` in protobuf-es and the field's own name in ts-proto's `oneof=unions`, and by a comparison (`===`, `!==`, `==`, `!=`) or a `switch` `case` clause of the discriminant against the constituent's string literal, read from the syntax. An access on the union control flow has not narrowed, and a read of the discriminant compared with no literal, reads every constituent it names. The constituent whose discriminant is `undefined` binds nothing.

**references-ts.33** TypeScript's encoding serializers are `toBinary`, `toJson` and `toJsonString`, and ts-proto's generated `<Msg>.encode` and `<Msg>.toJSON`; `fromBinary`, `fromJson`, `fromJsonString`, `mergeFromBinary`, `mergeFromJson`, `<Msg>.decode`, `<Msg>.fromJSON`, `<Msg>.fromPartial`, `<Msg>.create` and `create` write; `clone` passes its argument through; `equals` reads every field. ts-proto's generated client bodies are transport. A TypeScript enum value's name conversion, a reverse lookup by an index that is not a literal, a call of a generated `<enum>ToJSON`, or a read of the enum descriptor's `values` array or `value` record, reads every value of the enum.

**references-ts.34** A TypeScript consumer carries `cap` `persistence` when hand code passes its message's schema, or a schema whose fields reach it, to `fromJson`, `fromJsonString` or `mergeFromJson` without `ignoreUnknownFields: true`, and `cap` `descriptor-exposure` when hand code serves the file's descriptors through a server reflection handler or encodes its file descriptor as a descriptor message.

## Literal requires
