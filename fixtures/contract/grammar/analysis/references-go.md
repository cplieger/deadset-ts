# References in Go

Rules `references-go.1` to `references-go.17` of [the analysis](../analysis.md). A rule is cited by its id, which is never reused for another rule.

## Uses through memory layout

**references-go.1** In Go, a conversion of a pointer to `unsafe.Pointer`, or of an `unsafe.Pointer` to a pointer type, reads and writes every field the pointed-to type lays out, recorded at the conversion: every field of it where it is a struct type, every field of its element type where it is an array type, and so on through every field of a struct type and every element of an array type it holds, at any depth. A field or an element holding a pointer, a slice, a map, a channel, a function or an interface is itself read and written, and the use goes no further into the storage it refers to, which the pointed-to type does not lay out. Where the pointed-to type is a type parameter, or a struct or array type that holds one at any depth, the conversion has the same use of each type argument that type parameter takes in an instantiation the program holds, an instantiation made through another generic declaration's own type parameters included, because the instantiated type is the one the conversion lays out. A struct type that declares a field of type `structs.HostLayout` has the same use of every field it lays out, recorded at that field, because its layout is fixed for code outside the program. Code that reads memory through either names no field, so no field such a use reaches is reported under `DS1003` or `DS1301`.

## Conversions an outside program writes

**references-go.2** In a Go library, a program outside the analysis that imports the published API can hand a value it holds to any published parameter the value's type fits. A published function is an exported function of a package of the published API, an exported method selectable on a value of a type an outside program can hold, a method promoted through an embedded field of any visibility included, and an exported method of an interface type the published API reaches, as the confidence rule below states what the published API reaches, and a published parameter is a parameter of a published function.

**references-go.3** An outside program can hold a value of each exported type a package of the published API declares, and of each type the published API hands it: the type of a result of a published function, of an exported variable and of an exported constant of a package of the published API, and of each exported field selectable on a value of a type it can hold, a field promoted through an embedded field of any visibility included, and the type of a parameter of a function type that a published parameter has and of a parameter of a method of an interface type the published API reaches, because the published code calls such a function or method with values of its own. It can hold as well the element, key and result types of a pointer, slice, array, map, channel or function type it can hold, and so on until no further type joins. The analysis counts no value an outside program obtains only through type inference over a published function value, through reflection or through `unsafe`, so a type the published API reaches only as the type of a parameter of a published function is not one it counts as held.

**references-go.4** Where a published parameter's type is an interface type I, or its element type is one where the parameter is variadic, whichever package declares I and whether or not it is exported, the analysis records a site converting T to I, positioned at the parameter, for each type T the target declares that an outside program can hold, that is not an interface type and that implements I. For each type parameter of a published function, or of a generic type a package of the published API exports, whose constraint is an interface type I, however the declaration's parameters and fields spell the type parameter, the analysis records a site instantiating it with each such T that satisfies the constraint, positioned at the type parameter. Either site is a use by the declaration that declares the parameter or the type parameter, and the pair it records retains under the `interface-satisfaction` class of [`exemptions.json`](../../exemptions.json) as any other pair does.

**references-go.5** Two modelling bounds decide what implements I here, and each only retains more. A type T implements I where T or a pointer to T does, and the analysis does not model which of the two an outside program can form. A generic type implements I where some instantiation the type checker accepts could, which the analysis decides by matching each method of I to a method of the type of the same name with as many parameters and as many results, whatever their types.

**references-go.6** The sites are recorded only while the published API's reachability class, as the confidence rule below gives it, is `possible` or `probable`. Where every declared consumer loads, that class is `certain`, the consumers are the outside programs the run knows, and the conversions they write are the run's own sites.

**references-go.7** A constant specification of a parenthesized constant declaration that writes no expression list repeats the first expression list before it, and that list's type, as the language states. It therefore references each declaration that type and those expressions name, as the specification that writes them does. The reference is recorded at the specification's first name and held by each constant the specification declares.

**references-go.8** A selector of a field of an unnamed struct type references the field at the same position of every identical unnamed struct type the target spells, because identical unnamed struct types are one type and each spelling declares its own field objects. A struct type a type declaration declares is not unnamed, and two struct type literals whose tags differ are not identical.

## Schema bindings in Go

**references-go.9** A protoc-gen-go file of row `protoc-gen-go-1` names each declaration through the serialized file descriptor it embeds, `file_<f>_rawDesc`, written as a `[]byte` composite literal, as a `string([]byte{…})` conversion or as a string constant; the descriptor's `name` is the entry's schema file, and its package and declaration names are each record's `schema`. `file_<f>_goTypes` lists the enums, then the messages in the order the descriptor declares them, a `nil` entry standing for each map entry message, then the dependency types: the analyzer counts the `nil` entries, stops after as many enums and messages as the descriptor declares, and checks each entry's trailing `// i: <full name>` comment against the descriptor, a disagreement being `setup-failures.12`. A field binds through its struct field's `protobuf:"…"` tag by its number within its message's struct or one of its oneof wrapper types, never by the tag's `name=`, which names the message type for a group or `DELIMITED` field. An extension binds through its `protoimpl.ExtensionInfo` variable's `Field` and `Name`. The consumers are the row's: each message type, each field, each getter and `Has` and `Clear` method for its field, each oneof wrapper type and opaque `<Msg>_<Field>_case` constant for its member, each enum constant for its value and each extension variable.

**references-go.10** A protoc-gen-go-grpc file of row `protoc-gen-go-grpc-1` names each RPC by its `<Svc>_<Rpc>_FullMethodName` constant, or, before those constants exist, by the method name literal its `Invoke` call and its `grpc.ServiceDesc` carry, and its schema file by its `// source:` line. The consumer of each RPC is the `<Svc>Client` interface method; the consumers of the service are the `<Svc>Client` interface, `New<Svc>Client`, and the `<Svc>Server` interface outside a registration form. `Register<Svc>Server` is the registration function, and every method of a hand-written type converted to `<Svc>Server` that implements one of its methods is an implementer.

**references-go.11** A protoc-gen-connect-go file is row `protoc-gen-connect-go-1` when it imports `connectrpc.com/connect` and row `protoc-gen-connect-go-2` when it imports `connectrpc.com/connect/v2`, because neither major writes a version. It names each RPC by its `<Svc><Rpc>Procedure` constant and, where it writes one, by the `ByName` chain over its file descriptor's services and methods, and its schema file by its `// Source:` line. The consumer of each RPC is the `<Svc>Client` interface method; the consumers of the service are the `<Svc>Client` interface, `New<Svc>Client`, and the `<Svc>Handler` interface outside a registration form. The registration function is `New<Svc>Handler` in the first major and `Register<Svc>Handler` in the second, and the implementers are as `references-go.10` states, for `<Svc>Handler`.

**references-go.12** A protoc-gen-grpc-gateway file of row `protoc-gen-grpc-gateway-2` binds nothing. Its `request_<Svc>_<Rpc>_<n>` calls of `client.<Rpc>` and its `local_request_<Svc>_<Rpc>_<n>` calls of `server.<Rpc>` are forwarding, which `bindings.13` does not follow, and `Register<Svc>HandlerServer` converts its server argument to `<Svc>Server`, so that argument's methods are implementers.

**references-go.13** A protoc-gen-go-vtproto file binds nothing and lists serializers: `MarshalVT` and `SizeVT` encode, `UnmarshalVT` writes, `CloneVT` passes its receiver through and `EqualVT` reads every field, as `proto.Equal` does.

**references-go.14** Go's generated transport is `Invoke`, `NewStream`, `SendMsg` and `RecvMsg` in protoc-gen-go-grpc output; `CallUnary`, `CallServerStream`, `CallClientStream`, `CallBidiStream`, `CallClientStreamSimple`, `CallBidiStreamSimple` and the `connect.NewRequest` that wraps a plain request in connect-go output; and `Send`, `Receive` and `CloseSend` on a connect client or server stream. A hand-written call of `connect.NewResponse`, a construction of `connect.Request` and a grpc stream's `Send` passing a message are hand-site transport. The dispatch forms are `srv.(<Svc>Server).<Rpc>` in a grpc handler, the method values `New<Svc>Handler` passes to `connect.NewUnaryHandler` and its siblings, `h.svc.<Rpc>` in a connect-go second-major adapter, and `server.<Rpc>` in a gateway's `local_request_` function.

**references-go.15** A Go oneof member is read by a type-switch case or a type assertion naming its wrapper type, by a read of the wrapper's own field, and, in the hybrid and opaque APIs, by a comparison or `switch` case naming its `<Msg>_<Field>_case` constant against a `Which<Oneof>()` result; a composite literal of the wrapper writes it. The `_not_set_case` constant binds nothing, and neither do the oneof's interface field and its `Get<Oneof>()` getter themselves. A read of either, or of a `Which<Oneof>()` result, that is neither a type-switch operand nor compared with a case constant reads every member, and a `default` clause reads nothing further.

**references-go.16** Go's encoding serializers are `proto.Marshal`, `proto.MarshalOptions.Marshal` and `Size`, `proto.Size`, `protojson.Marshal`, `protojson.MarshalOptions.Marshal` and `Format`, `protojson.Format`, `prototext.Marshal`, `prototext.MarshalOptions.Marshal` and `Format`, `prototext.Format`, `MarshalVT` and `SizeVT`; their `Unmarshal` counterparts and `UnmarshalVT` write; `proto.Clone` and `CloneVT` pass their argument through; `proto.Equal` and `EqualVT` read every field. A Go enum value's name conversion, a call of the generated `String` method on a value of the enum type, a read of `<Enum>_name` or `<Enum>_value`, or of the enum descriptor's `Values()`, reads every value of the enum.

**references-go.17** A Go consumer carries `cap` `persistence` when hand code passes its message type, or a message type whose fields reach it, to `protojson.Unmarshal` or to `protojson.UnmarshalOptions` without `DiscardUnknown: true`, and `cap` `descriptor-exposure` when the program that links its generated file calls `reflection.Register`, `grpcreflect.NewHandlerV1` or `grpcreflect.NewHandlerV1Alpha`, or passes its file descriptor to `protodesc.ToFileDescriptorProto`, which marks that file's records only.
