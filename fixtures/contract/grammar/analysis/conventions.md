# Convention rows

Rules `conventions.1` to `conventions.12` of [the analysis](../analysis.md). A rule is cited by its id, which is never reused for another rule.

**conventions.1** An analyzer may carry a table of convention rows, each the data of one framework's file-system conventions. A row has a name, an enabling package, a version range in the semantic-versioning range syntax, the globs of its entry files, the globs of the files it excludes, the directories its framework generates, the configuration properties that move a directory those globs or a generated directory name, each with the configuration files the property is read from and, for a property that is an option of a call, the module and the exported name of the function called, the configuration properties whose value names a package by a short name, each with the configuration files it is read from and the package name the value stands for, written with `{}` where the value goes, the selection keys, the configuration properties whose value only selects files to test, to mutate, to cover or to ignore, each with the configuration files it is read from, the package keys, the members of a configuration file whose strings name the packages its tool loads, each with the configuration files it is read from, the manifest keys, the members of a `package.json` its tool reads its configuration from, the manifest entry keys, the members of that `package.json` whose strings name the tool's entries, each naming a directory of entries or one entry, the prefixed-name properties, the configuration properties whose value names a package by its tool's prefix convention, each with the configuration files it is read from, the prefix and the marker a value starts with, if any, and the test-file properties, the configuration properties whose value names a file the tool's test runner loads beside the tests, each with the configuration files it is read from and the properties its paths resolve against. The table is part of the analyzer, versioned with it, and no configuration key adds a row.

**conventions.2** A row applies when a `package.json` the analysis reads declares the enabling package as a dependency, a development dependency, a peer dependency or an optional dependency, and the version the installed package's own `package.json` names, found from that manifest's directory as the compiler resolves a package, is in the row's range. An enabling package declared as a dependency or a development dependency whose installed manifest the analysis cannot find is the setup failure `missing-module`, except in a nested package's manifest, where it applies no row and raises no setup failure, because no run requires a nested package to be installed. An enabling package declared only as a peer dependency or an optional dependency whose installed manifest the analysis cannot find applies no row and raises no setup failure. An applied row's globs are matched against the directory of the manifest that declared the package, each against a source file's own path and against each output path the emit mappings of the configuration holding the file write it to, so a glob naming build output names the source that output is compiled from: every file an entry glob matches and no exclude glob matches is a root, as an entry of `ts.entry_files` is, and every file below a directory the row names as generated, read against the same directory, is a generated file, whose declarations the `generated-file` class of [`exemptions.json`](../../exemptions.json) retains. A generated directory a configuration property moves is read where the property sets it, as an entry glob's directory is, so a code generator whose configuration names its output directory, a CSS-in-JS tool's `outdir` among them, is described by a row whose only content is that generated directory.

**conventions.3** A property that moves a directory is read from the row's configuration file without running it, in the objects the row reads there. Where the property is not an option of a call, the object is the file's default export, in each of its forms: the expression `export default` writes, the value assigned to `module.exports`, the binding an `export { name as default }` specifier names, and the document of a JSON configuration file. A configuration file whose name ends with `.yml` or `.yaml` is read as the JSON value its YAML document denotes, in the subset tool configurations write: block and flow mappings and sequences, and plain, single-quoted and double-quoted scalars, a plain scalar read under the YAML core schema, with comments. A document that uses anything else, an anchor, an alias, a tag, a block scalar, a complex key or a second document, holds no object to read, as a JSON document that does not parse holds none. No property that moves a directory is read from such a file, because a failure names a line of the file's text. A default export that names a top-level `const`, `let` or `var` binding is read through to that binding's initializer, and one that is a call is read through to the call's first argument, until an expression that is neither. Where the property is an option of a call, the objects are the first arguments of every call in the file to the row's function, imported from the row's module by its exported name under any local name, or called through a namespace import of that module; an argument that names a top-level binding is read through to its initializer, and no further call is followed. In a file that declares no binding named `require`, a top-level `const`, `let` or `var` declaration whose initializer is a call of `require` with the row's module as its one argument, written as a string literal, binds as an import of that module does. An object binding pattern binds each exported name it lists under its local name, as a named import does, and a binding that is a name binds a namespace import. Parentheses, `as`, `satisfies` and the non-null assertion are read through wherever an expression is. A call with no argument, and a file with no object to read, set nothing.

**conventions.4** The property is a path of keys through nested object literals, each key matching a property whose name is an identifier, a string literal or a template literal with no substitution, or a computed name whose expression is a string literal or a template literal with no substitution. Where the value at the end of the path is a string literal or a template literal with no substitution, the globs read each directory so set; where no object the row reads sets the property, the globs read the default directory. The row is the setup failure `convention-not-literal` where the value at the end of the path is anything else, a template literal with a substitution, a concatenation, a call and a name among them; where a value along the path is not written as an object literal, a name bound to an object literal among them, because a key's value is not read through a declaration; where the object the row reads is not written as an object literal, a default export that is a function or a class among them; and where the object the row reads or an object along the path holds a spread, or a computed name whose expression is not a string literal, a numeric literal or a template literal with no substitution, because either may set any key. An object the row does not read, the options of another function in the same file among them, sets nothing and raises no failure.

**conventions.5** A property that names a package by a short name is read from an applied row's configuration files as a property that moves a directory is, and a string value at the end of its path, or a string element of an array value there, stands for the package name the row writes with that string in place of `{}`. A declared dependency of that name is used. Where the value is not a literal, every declared dependency whose name the row's package name can produce with some value in place of `{}` is used, and the row raises no setup failure for the property. A string value equal to a declared dependency's own name is a use under the strings rule above whatever the row says.

**conventions.6** A prefixed-name property is read as a property that names a package by a short name is, and a string value at the end of its path, or a string element of an array value there, names a package by the prefix convention: a name `x` stands for `<prefix>-x`, a scope `@s` alone for `@s/<prefix>`, a scoped name `@s/x` for `@s/<prefix>-x`, and a name that already starts with `<prefix>-`, or a scoped name whose second part does, for itself. Where the property has a marker, only a value that starts with the marker names a package, its name the text between the marker and the value's last `/`, so `plugin:react/recommended` names `react`. Where it has none, a value holding a `:` or starting with `.` or `/` names none, and the name ends at the value's first `/` past a scope, so `airbnb/hooks` names `airbnb`. A declared dependency so named is used. A value that is not a literal uses nothing under this rule and raises no setup failure.

**conventions.7** A selection key is read from an applied row's configuration files as a property that moves a directory is. A string value at the end of its path, or a string element of an array value there, roots no file under the strings rule above, because the tool reads a file it selects only when another key runs or loads that file. A key that runs or loads a file is no selection key, so a string it holds roots the file it names. A selection key whose value is not a literal raises no setup failure, and every string the file holds elsewhere is read under the strings rule.

**conventions.8** A manifest entry key is read from the `package.json` that declared the row's enabling package, a key path whose `*` stands for every member of the object it reaches. Every string at any depth of the value there, a JSON object member's name excepted, read against that manifest's directory with leading `./` segments dropped, writes an entry glob: for a key naming a directory, every module below it, and a string holding a glob character names none; for a key naming an entry, the string itself and the string followed by a JavaScript or TypeScript extension. A string that leaves the manifest's directory writes none. The globs are matched as the row's own entry globs are, so a key naming build output roots the source the emit mappings read it back to.

**conventions.9** A manifest key is read from the `package.json` that declared the row's enabling package. Every string at any depth of that member's value, a JSON object member's name excepted, that equals the name of a dependency the manifest declares, or that name followed by `/` and a subpath, is a use of the dependency. A string under a member that no applied row names as a manifest key is no use of a dependency under this rule.

**conventions.10** A package key is read from each of an applied row's configuration files, in the objects the row reads there as it reads a property that moves a directory, the document of a file whose name ends with `.json` among them. Every string at any depth of the value of a member of that name, a JSON object member's name excepted, at any depth of those objects, that equals the name of a dependency the manifest that declared the row's enabling package declares, that name followed by `/` and a subpath, or that name followed by `:` and a name, is a use of the dependency, so a string `"@example/tool:build"` under a package key `builder` uses `@example/tool`. Such a string uses no other dependency itself, and a string under a member that no applied row names as a package key is no use of a dependency under this rule. A declared peer of a dependency it uses is needed as the precondition of `DS1701` in [`kinds.json`](../../kinds.json) states.

**conventions.11** A test-file property is read from an applied row's configuration files as a property that moves a directory is. Each string value at the end of its path, or string element of an array value there, read against the directory the row's resolving properties give, or else the configuration file's own directory, names a test file, as a file `ts.test_files` names is one, because the runner loads the file only to run tests. A file a test-file property names is not rooted by the strings rule.

**conventions.12** The configuration's own keys win. A row `ts.disabled_conventions` names does not apply, adds no root and raises no setup failure, and the entries of `ts.entry_files` are roots whether a row applies or not. A row only adds roots, uses, retentions and test files. The report lists each row it applied in `conventions_applied`.
